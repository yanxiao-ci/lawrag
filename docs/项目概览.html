法律法规智能问答系统（lawrag）

一个中文法律领域的 RAG 问答系统：快问快答通道承接能精确命中的问题（原句、条文号引用）， 其余交给 RAG 通道——法条与问答双路召回、精排后送进上下文，让大模型基于检索到的条文作答； 每条结论都标注《法律名》第 X 条，生成后还有引用校验。全链路 4 类可复现评测。

一项目亮点

亮点做法实测结果
快通道门控重标定 把命中判据从"全库 softmax 分数"换成词面判据（法条通道看查询词覆盖率、问答通道看词集合 Jaccard），阈值用 200 条库内原句 + 100 条真实问题标定 错误抢答 54 → 0；真实法律问题进 RAG 10% → 99%；库内原句 200/200 仍秒回
法条级分块 不用固定长度切分：子块 = 一条完整法条（天然带条文号，便于引用），父块 = 同法连续 5 条（上下文完整） 21,565 条法条 → 55,847 子块 / 4,352 父块；抽样解析率 100%
混合检索 + 精排 BGE-M3 稠密 + 稀疏双路召回 → WeightedRanker 粗排 → 父块去重 → BGE-Reranker 精排取 Top-2 Recall@5 0.824；MRR 0.7150 → 0.7188；检索耗时 69 → 237 ms
第三召回源 把 2 万条法律问答单独建向量集合接入 RAG（法条集合强制时效过滤，问答无该字段，故独立建集合） 参考条文覆盖率 65% → 75%；兜底拒答率 24% → 5%
条文号精确路由 查询出现《X法》第 Y 条时直查 MySQL，返回条文 + 编/章/节 + 施行日期；有历史版本时主动提示 确定性查询不走向量检索，0.3 秒返回
时效与引用安全 法条带状态（有效/已修改/已废止），检索常开 status == "有效" 过滤；生成后抽取回答里的条号回查上下文 不过滤时粗排前 8 条会混进 3 条旧条文；校验可拦住编造的条号
工程取向：所有指标都用 tools/ 下的脚本产出，能一条命令复现；评测里刻意保留三类不依赖大模型打分的指标， 避免"换个裁判分数就变"。

二系统架构与业务流程

三段式：离线准备（法条与问答入库）→ 在线问答（两条通道 + 三个判断点）→ 评估迭代（四类评测闭环）。

三个判断点（在线链路的关键设计）

判断点为什么放在这里
问候语纯规则的事不走模型，直接模板回复
条文号精确路由用户已经指名条文，这是确定性查询，不该交给向量库去"猜"
快通道门控只对"同一个问题 / 查询本身就是这条条文"秒回，其余交给 RAG——便宜、确定性的先走，需要理解的后走

五工程化与部署

接口

POST /api/query一次性问答
WS /api/stream流式问答（前端默认）
POST /api/create_session新建会话
GET|DELETE /api/history/{id}会话历史
GET /api/sources · GET /health来源 / 存活检查

工程要点

  • 流式输出（WebSocket 推 start / token / end）
  • 会话历史落 MySQL，只带最近 5 轮
  • 答案缓存 Redis，TTL 7 天
  • 日志 10MB × 5 轮转；关键节点打点
  • 配置 .env > config.ini > 代码兜底
  • Docker Compose 编排应用；MySQL / Redis / Milvus 独立部署
  • 自检脚本一次跑完 10 项（最多 1 次模型调用）

六快速开始

# 1) 依赖服务：MySQL 3307 / Redis 6379 / Milvus 19530（任意主机均可，改 .env）
# 2) 安装依赖
pip install -r requirements.txt
# 3) 建库（顺序不能换）
python tools/import_law_data.py            # 法条 + 问答入库 MySQL
python tools/build_law_index.py --reset    # 法条向量库
python tools/build_lawfaq_index.py --reset # 问答向量库（第三召回源）
# 4) 启动
python app.py                              # 浏览器打开 http://127.0.0.1:8080/

自检：python tools/smoke_test.py（10 项检查，最多 1 次模型调用； 加 --no-llm 完全不出网）。

语料来自公开法律法规与法律问答数据集，模型通过云端 API 调用；输出不构成法律意见，请勿用于真实法律决策。

页面内所有指标均可用仓库 tools/ 下的脚本复现；流程图源码 docs/make_flowchart.py。
